  useListCrmRejectionReasons   -> CrmRejectionReason[]
  useCreateCrmLeadNote / useUpdateCrmLeadNote
  useCreateCrmLeadTask / useUpdateCrmLeadTask
  useListMyCrmTasks            -> CrmMineTask[]

getGetCrmLeadQueryKey(), getGetCrmLeadContextQueryKey(),
getListMyCrmTasksQueryKey(), getListCrmRejectionReasonsQueryKey().
Never write a query key as a string literal.

ERROR TEXT COMES FROM THE SERVER
The server returns Hebrew messages in { error }. Display that string.
Do NOT hardcode a second copy of it in the UI - if the two ever disagree
the user is told something false. These are the real strings, listed so you
recognise them, NOT so you reproduce them:
  "חובה ליצור משימה עם תאריך"
  "לא ניתן להזין תאריך שעבר"
  "סטטוס זה מתעדכן אוטומטית בעת קליטת תשלום"
  "לא ניתן להחזיר ליד לסטטוס חדש"
  "חובה לבחור סיבת דחייה"
  "סיבת הדחייה אינה תקינה"
  "חובה להוסיף פירוט לסיבת הדחייה"
  "לא ניתן לערוך הערה לאחר 15 דקות"
Client-side validation is welcome as a convenience, never as the authority.

BUILD

1. Status change on the lead card - pages/crm/lead-detail.tsx
   The status badge becomes a control that opens a dialog.
   - The picker lists statuses from useListCrmLeadStatuses but EXCLUDES
     "paid" and "new". The server rejects both; do not offer them.
   - Choosing "pipe" or "long_followup" reveals a required task section in
     the SAME dialog: title and due_at. Cancelling the dialog cancels the
     whole action - nothing is sent and the status does not change.
   - Choosing "not_relevant" reveals a reason picker from
     useListCrmRejectionReasons. When the chosen reason has
     requires_detail true, a free-text field appears and is required.
   - One submit sends one useChangeCrmLeadStatus call carrying whichever
     of task / rejection applies.
   - On success invalidate ALL of: the lead, the lead context, the leads
     list, AND the lead-statuses list. The tab badges are derived from
     status counts, so skipping the last one leaves stale numbers on screen.
   - On failure keep the dialog open and show the server's message.

2. Notes on the lead card
   - Adding a note is ONE textarea and ONE button, inline on the card. No
     separate screen and no dialog, and the scroll position must survive
     the submit.
   - Newest first.
   - Show an edit affordance only when the note's user_id is the current
     user AND created_at is less than 15 minutes ago. Editing is inline.
   - A note that has edited_at set shows a quiet "נערך" marker.
   - There is no delete. Do not add one.

3. Tasks on the lead card
   - A create form: title, optional description, due_at. Past dates
     disabled in the picker.
   - Each open task gets a "בוצע" action (useUpdateCrmLeadTask, status
     "done"). Done tasks stay visible, struck through, sorted after the
     open ones.
   - Show the task's source: "אוטומטי" for status_auto, "ידני" for manual.
     Never print the raw English value.

4. The reminder modal - components/crm/task-nudge-provider.tsx
   - Mount it ONCE in App.tsx inside AuthGate, as a sibling of <Router />.
     It must not be inside any page.
   - Poll useListMyCrmTasks with refetchInterval 60000.
   - Render a blocking centred modal above all content: the task title, the
     lead name and phone, and a link to /crm/leads/:lead_id.
   - EXACTLY two actions. "בוצע" sets status "done". "דחה" sets
     snoozed_until to one hour from now. Both then refetch the feed.
   - NO close X, NO click-outside dismiss, NO Escape dismiss.
     **You cannot use the shared DialogContent for this** - it hardcodes an
     X close button at components/ui/dialog.tsx:46, and components/ui/ is
     off limits. Compose Radix Dialog primitives yourself inside
     components/crm/, or use a plain fixed overlay. Whichever you pick,
     handle onEscapeKeyDown and onInteractOutside by preventing default.
   - If several tasks are due, show them ONE AT A TIME as a queue. Never
     stack modals.
   - The modal must never appear while the feed is empty or still loading.

5. Overdue counter
   Put a count badge on the existing "מרכז CRM" sidebar entry in
   components/layout/sidebar.tsx, fed by the same useListMyCrmTasks query.
   Hide it at zero.
   Do NOT modify components/layout/shell.tsx - it is the layout for every
   existing page in the app.
