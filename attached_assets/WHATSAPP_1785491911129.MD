Build a Hebrew (RTL) internal web app called "WhatsApp Review Board" for a video editor to review AI-drafted replies to client WhatsApp messages and score them. Stage 1 is a learning loop: no messages are sent from this app — the editor only reviews, scores, and optionally rewrites the AI's proposed reply.

TECH STACK
- Next.js (App Router) + TypeScript + Tailwind CSS.
- Supabase via @supabase/supabase-js, used ONLY from server-side code (API routes / server actions). Never expose the service-role key to the browser.
- Simple shared-password gate: a single password stored in env var APP_PASSWORD; on login, set an httpOnly cookie. All pages require it.

ENV VARS (I will fill these in Replit Secrets)
- SUPABASE_URL
- SUPABASE_SERVICE_ROLE_KEY
- APP_PASSWORD

DATA SOURCE
Supabase table: public.whatsapp_messages
Columns:
  id (bigint, pk), created_at (timestamptz), wa_message_id (text),
  received_at (timestamptz), customer_wa_id (text), customer_name (text),
  message_type (text), message_text (text), media_url (text),
  category (text), subcategory (text), intent (text), sentiment (text),
  urgency (text), language (text), ai_analysis (text), proposed_reply (text),
  ai_confidence (int), suggested_action (text),
  editor_score (int, 1-5, nullable), editor_corrected_reply (text, nullable),
  editor_notes (text, nullable), review_status (text: 'pending' | 'reviewed'),
  reviewed_at (timestamptz, nullable), raw_payload (jsonb)

The app READS all analysis columns and WRITES ONLY these:
  editor_score, editor_corrected_reply, editor_notes, review_status, reviewed_at.
Never write to any other column.

LAYOUT — two-pane "conversations" view (RTL)
1. Left sidebar: list of conversations grouped by customer_wa_id. Each item shows customer_name (fallback to the number), the last message snippet, time of last message, and a badge with the count of that customer's messages still in review_status='pending'. Sort by most recent message first. A top filter toggles: "ממתין לביקורת" (pending) / "הכל" (all).
2. Main pane: when a conversation is selected, show all that customer's messages in chronological order as chat bubbles (incoming, right-aligned RTL). Under EACH message render an "AI + scoring" card containing:
   - AI analysis block (read-only): category, subcategory, sentiment, urgency, ai_confidence (show as a small bar/percent), intent, ai_analysis.
   - suggested_action shown as a colored tag (auto_reply = green, needs_human = amber, ignore = gray).
   - "תשובה מוצעת" (proposed_reply) shown read-only.
   - Scoring form:
       * editor_score: 1–5 star selector (required to mark reviewed).
       * editor_corrected_reply: textarea, pre-filled with proposed_reply so the editor can tweak it.
       * editor_notes: optional textarea.
       * Save button "שמור וסמן כנבדק" → writes the fields, sets review_status='reviewed' and reviewed_at=now(), then updates the UI (row moves out of "pending", badge updates) without a full reload.
   - If review_status is already 'reviewed', show the saved score/notes and an "ערוך" button to re-open the form.

ADD AN ANALYTICS PAGE at route /analytics (linked from the top bar, Hebrew RTL).
All metrics computed server-side over the whatsapp_messages table. Use Recharts for charts.

DEFINE "reply match" (how close the AI's proposed_reply was to what the editor kept):
- For each REVIEWED row: if editor_corrected_reply is null/empty → the editor accepted the AI reply as-is → matchScore = 1.0 (100%).
- Else compute a normalized similarity between proposed_reply and editor_corrected_reply using normalized Levenshtein similarity (1 - levenshtein/maxLen), server-side. matchScore = that value (0..1).
- "acceptanceRate" for a group = share of reviewed rows with matchScore >= 0.9 (i.e. the editor barely changed it).
- "avgMatch" for a group = average matchScore.

SECTIONS
1. KPI row (over reviewed rows): total reviewed, avg editor_score (1–5), overall acceptanceRate %, overall avgMatch %.
2. Per-category table (one row per category), sorted by avg editor_score ascending (worst first, so the editor sees where Claude is weakest):
   columns: category, count, avg editor_score, avg ai_confidence, acceptanceRate %, avgMatch %.
   Color the avg-score cell red/amber/green by thresholds (<3 red, 3–4 amber, >4 green).
3. Score distribution: bar chart of counts for scores 1,2,3,4,5.
4. suggested_action breakdown: for each suggested_action (auto_reply / needs_human / ignore) show count and avg editor_score — this tells us whether "auto_reply" suggestions really get high scores (safe to auto-send later).
5. Confidence calibration chart: bucket ai_confidence into 0–20, 21–40, 41–60, 61–80, 81–100; for each bucket plot avg editor_score. Goal: verify that higher AI confidence → higher editor score.
6. Trend over time: group reviewed rows by day (received_at); line chart of daily volume and daily avg editor_score.
7. "Needs attention" list: the 10 reviewed rows with the LOWEST matchScore (biggest gap between AI reply and editor's rewrite), showing customer_name, category, proposed_reply vs editor_corrected_reply side by side — these are the best training examples of where Claude got it wrong.
