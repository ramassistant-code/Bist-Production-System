Goal of this phase:
Build the foundation for the pricing system:
- Products / services catalog
- Components catalog
- Product components composition
- Cost calculation
- Price fields
- Active/inactive status
- Clean CRUD flows

Important business logic:
A product is something we can later add to a quote.
A component is an internal cost/building block that can be attached to a product.
For example:
- Product: "צילום פודקאסט שעה"
- Components: "מפעיל", "אולפן", "מצלמות", "עריכה", "אחסון", etc.

6. Product components composition

Inside product details/edit screen, implement the ability to attach components to a product.

For each attached component:
- Select component from existing active components
- Quantity
- Unit cost snapshot
- Total component cost = quantity × unit cost snapshot
- Notes

Important:
- When attaching a component to a product, save the current component cost as a snapshot.
- If the component cost changes later, it should not automatically change old product compositions unless the user updates it manually.
- Add a button:
  "עדכן עלות לפי מחיר רכיב נוכחי"
- Add a button:
  "הסר רכיב מהמוצר"

Calculated fields:
- Product calculated cost = sum of all attached components total cost
- Gross profit = sale price - calculated cost
- Gross profit % = gross profit / sale price × 100
- If sale price is 0, do not divide by zero. Show "לא ניתן לחשב".
